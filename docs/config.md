# Configuration Reference

FederLoom reads a single YAML config file passed via `--config /path/to/config.yaml`.
All fields are optional — unset fields fall back to the defaults defined in
`internal/config/config.go:Defaults()`. Duration values use Go notation:
`168h`, `30m`, `1s`, `500ms` — the `d` suffix is not accepted.

## The two-file pattern

Most deployments use two files:

- **`config.yaml`** — committed to version control. Contains all non-secret
  settings: federation mode, ingest sources, enforcement backend, scoring
  thresholds. Never put credentials here.
- **`config.local.yaml`** — generated by the bootstrap script for each node.
  Contains secrets (`api_key`, `crowdsec_machine_password`). Gitignored — never
  commit it.

> **For operators:** In Docker deployments `config.local.yaml` is mounted directly
> as `/etc/federloom/config.yaml:ro` — it is a *complete standalone config*, not a
> patch on top of `config.yaml`. The bootstrap script copies all non-secret fields
> from `config.yaml` into `config.local.yaml` and adds the secrets. FederLoom
> performs no YAML merging at runtime; the daemon sees exactly one file.

> **For developers:** The loading path is `config.Load(path)` →
> `os.ReadFile` → `yaml.Unmarshal` into `config.Defaults()`. There is no
> second-file merge in `internal/config/config.go`; that convention lives
> entirely in the bootstrap scripts and Docker Compose volume mounts.

## Federation modes

Set with the top-level `federation_mode` key. Default: `solo`.

| Mode | Description |
|------|-------------|
| `solo` | Local detection and enforcement only. No P2P transport, no peer gossip. `discovery.*` flags are no-ops. |
| `isolated` | Runs a private trust domain with its own root. Does not import reputation from other domains. |
| `federated` | Full participation: contributes events to and imports consensus from the broader swarm, weighted by `trust.federation_discount`. |

## Field reference

The sections below cover every config key accepted by FederLoom. Fields marked
**[secret]** must go in `config.local.yaml` and must never be committed.

### store

Controls the BadgerDB reputation store.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `store.dir` | string | `data/reputation` | Directory for BadgerDB files and derived paths (identity key, anchors, whitelist). Relative paths are resolved from the working directory of `federloomd`. |

```yaml
store:
  dir: /var/lib/federloom
```

### reputation

Tunes the scoring engine and decay behaviour.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `reputation.half_life` | duration | `168h` | Score half-life for exponential decay. After this interval an IP's score halves. Lower = faster forgiveness. |
| `reputation.block_threshold` | float64 | `75` | Score at which an IP is added to the blocklist. |
| `reputation.unblock_threshold` | float64 | `60` | Score below which a previously blocked IP is removed from the blocklist. Must be ≤ `block_threshold`. |
| `reputation.decay_interval` | duration | `1h` | How often the decay GC runs. Lower = smoother decay, higher CPU cost. |
| `reputation.rules_file` | string | `""` | Path to `rules.yaml`. Empty string means legacy threshold mode (block when score ≥ `block_threshold`). Default auto-discovery: `<store.dir>/rules.yaml` (absent = legacy mode). |
| `reputation.ipv6_prefix` | int | `64` | IPv6 reputation and enforcement granularity. IPv6 addresses are normalized to this prefix, so an attacker's whole allocation aggregates to one reputation entry and blocks as one firewall range. Use `56` for router-sized allocations. IPv4 is always keyed per single address. Valid range `1`–`128`; out-of-range values fall back to `64`. Note: to shield an IPv6 range from blocking, never-block and `extra_whitelist` entries must be at least as wide as this prefix (e.g. a `/64` or shorter prefix); a narrower entry such as a single `/128` will not protect the enclosing `/64` block. |

```yaml
reputation:
  half_life: 168h           # 7 days
  block_threshold: 75
  unblock_threshold: 60
  decay_interval: 1h
  rules_file: /etc/federloom/rules.yaml
  ipv6_prefix: 64
```

### ingest

All ingest adapters are opt-in (`enabled: false` by default). Enable only the
sources relevant to your deployment.

#### ingest.honeypot

Tails Cowrie SSH honeypot JSON logs.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ingest.honeypot.enabled` | bool | `false` | Enable the Cowrie log adapter. |
| `ingest.honeypot.log_file` | string | `""` | Absolute path to `cowrie.json`. |
| `ingest.honeypot.poll_interval` | duration | `1s` | How often to check the log file for new lines. |

```yaml
ingest:
  honeypot:
    enabled: true
    log_file: /var/log/cowrie/cowrie.json
    poll_interval: 1s
```

#### ingest.opencanary

Tails OpenCanary JSON logs (multi-protocol honeypot).

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ingest.opencanary.enabled` | bool | `false` | Enable the OpenCanary log adapter. |
| `ingest.opencanary.log_file` | string | `""` | Absolute path to `opencanary.log`. |
| `ingest.opencanary.poll_interval` | duration | `1s` | How often to check the log file for new lines. |

```yaml
ingest:
  opencanary:
    enabled: true
    log_file: /var/log/opencanary/opencanary.log
    poll_interval: 1s
```

#### ingest.mailcow_logs

Reads Postfix and Dovecot container logs via `docker logs --since=<timestamp>`.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ingest.mailcow_logs.enabled` | bool | `false` | Enable the Mailcow native log adapter. |
| `ingest.mailcow_logs.postfix_container` | string | `""` | Docker container name for Postfix. Typical value: `mailcowdockerized-postfix-mailcow-1`. |
| `ingest.mailcow_logs.dovecot_container` | string | `""` | Docker container name for Dovecot. Typical value: `mailcowdockerized-dovecot-mailcow-1`. |
| `ingest.mailcow_logs.poll_interval` | duration | `30s` | How often to call `docker logs`. |

```yaml
ingest:
  mailcow_logs:
    enabled: true
    postfix_container: mailcowdockerized-postfix-mailcow-1
    dovecot_container: mailcowdockerized-dovecot-mailcow-1
    poll_interval: 30s
```

#### ingest.spamtrap

Tails a log file where one attacker IPv4 per line is written by an MDA rule
or script when mail hits a spamtrap address.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ingest.spamtrap.enabled` | bool | `false` | Enable the spamtrap log adapter. |
| `ingest.spamtrap.log_file` | string | `""` | Absolute path to the spamtrap log. |
| `ingest.spamtrap.poll_interval` | duration | `1s` | How often to check the log file for new lines. |

```yaml
ingest:

    enabled: true
    log_file: /var/log/federloom-spamtrap.log

```

#### ingest.crowdsec

Reads decisions and alerts from a local CrowdSec LAPI. Two auth modes:

- **Bouncer** (`api_key`): read `/v1/decisions` only.
- **Machine** (`machine_id` + `machine_password`): read `/v1/decisions` and `/v1/alerts` via JWT. Required for `enable_alerts: true`.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ingest.crowdsec.enabled` | bool | `false` | Enable the CrowdSec LAPI adapter. |
| `ingest.crowdsec.lapi_url` | string | `""` | URL of the CrowdSec LAPI, e.g. `http://127.0.0.1:8080`. |
| `ingest.crowdsec.api_key` | string | `""` | **[secret]** Bouncer API key. Run `cscli bouncers add federloom` to generate. |
| `ingest.crowdsec.machine_id` | string | `""` | **[secret]** Machine account ID for alert access. |
| `ingest.crowdsec.machine_password` | string | `""` | **[secret]** Machine account password. |
| `ingest.crowdsec.poll_interval` | duration | `30s` | How often to poll the LAPI. |
| `ingest.crowdsec.enable_decisions` | bool | `true` | Ingest confirmed ban decisions. |
| `ingest.crowdsec.enable_alerts` | bool | `true` | Ingest alerts (requires machine auth). |

```yaml
ingest:
  crowdsec:
    enabled: true
    lapi_url: "http://127.0.0.1:8080"
    api_key: ""             # set in config.local.yaml — never commit
    poll_interval: 30s
    enable_decisions: true
    enable_alerts: false    # set true only when using machine auth
```

#### ingest.fail2ban

Polls `docker exec <container> fail2ban-client banned` on each tick and
converts active bans into reputation events.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `ingest.fail2ban.enabled` | bool | `false` | Enable the fail2ban Docker adapter. |
| `ingest.fail2ban.container` | string | `fail2ban` | Docker container name running fail2ban. |
| `ingest.fail2ban.poll_interval` | duration | `30s` | How often to poll `fail2ban-client banned`. |
| `ingest.fail2ban.jail_reasons` | map[string]string | `{}` | Override the reason code assigned per jail name (exact match). Example: `sshd: ssh-auth-bruteforce`. |

```yaml
ingest:
  fail2ban:
    enabled: true
    container: fail2ban
    poll_interval: 30s
    jail_reasons:
      sshd: ssh-auth-bruteforce
      postfix-sasl: smtp-auth-bruteforce
```

### enforce

Selects and configures the firewall enforcement backend. This section is
security-critical — changes require extra care and operator confirmation before
deployment (Invariant 7).

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enforce.backend` | enum | `ipset` | Firewall backend: `ipset`, `nftables`, or `crowdsec`. |
| `enforce.set_name` | string | `federloom` | Name of the ipset set or nftables set to manage. |
| `enforce.chain` | string | `DOCKER-USER` | iptables chain to install the ipset jump rule in. Legacy single-chain field; prefer `chains`. |
| `enforce.chains` | []string | `[]` | iptables chains to install the rule in. When set, overrides `chain`. |
| `enforce.nft_hook` | string | `input` | nftables hook point. Used only when `backend: nftables`. |
| `enforce.extra_whitelist` | []string | `[]` | IPs never blocked regardless of score. Use for peer nodes or infrastructure IPs. Never federated (Invariant 3). |
| `enforce.crowdsec_lapi_url` | string | `""` | CrowdSec LAPI URL for the `crowdsec` backend. |
| `enforce.crowdsec_machine_id` | string | `""` | **[secret]** Machine account ID for the `crowdsec` backend. |
| `enforce.crowdsec_machine_password` | string | `""` | **[secret]** Machine account password for the `crowdsec` backend. |
| `enforce.crowdsec_ban_duration` | duration | `0` | Ban duration sent to CrowdSec. `0` = use `reputation.half_life`. |

> **For operators:** Enforcement is O(1) — FederLoom manages a single ipset/nftables
> set and installs one jump rule. Never configure a backend that writes one firewall
> rule per IP (Invariant 4).

```yaml
enforce:
  backend: ipset
  set_name: federloom
  chains:
    - INPUT
    - DOCKER-USER
  extra_whitelist:
    - 10.0.0.1    # gateway
```

### trust

Tunes the social trust layer (spec §5.1). Every value is operator-overridable
(Invariant 1). File paths default to `<store.dir>/<filename>` when not set.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `trust.anchors_file` | string | `<store.dir>/anchors.json` | Path to the trust anchor list. Managed by `federloomctl trust`. |
| `trust.person_key_file` | string | `<store.dir>/person.key` | Path to this node's Person identity key (Ed25519). Generated on first run. |
| `trust.peer_cert_file` | string | `<store.dir>/peer.cert` | Path to this node's own vouching certificate. |
| `trust.anchor_weight` | float64 | `0.9` | Weight applied to events from fully anchored reporters. |
| `trust.stranger_weight` | float64 | `0.3` | Weight applied to events from un-vouched (stranger) reporters. |
| `trust.stranger_score_cap` | float64 | `15` | Maximum total score contribution strangers can add for a single IP. |
| `trust.federation_discount` | float64 | `0.5` | Weight multiplier per federation hop for non-anchored reporters. Encodes "trust rises slowly" (Invariant 5). |
| `trust.blocked_peers_file` | string | `<store.dir>/blocked-peers.json` | Path to the blocked-peers list. Managed by `federloomctl trust block-peer`. |

```yaml
trust:
  anchor_weight: 0.9
  stranger_weight: 0.3
  stranger_score_cap: 15
  federation_discount: 0.5
```

### `federation_aggregators`, `federation_query_timeout`, `federation_query_cache_ttl`

When a reputation lookup (DNSBL or the per-IP score API) misses the local store,
the node queries these trusted aggregator peers on demand over libp2p and caches
the answer. `federation_aggregators` is a list of aggregator multiaddrs (empty =
feature off). `federation_query_timeout` (default `150ms`) bounds each query;
`federation_query_cache_ttl` (default `5m`) caches answers.

Aggregators are trusted like anchors — their answer is advisory evidence and
your own threshold decides "listed". The DNSBL/API stay on the private interface;
the query itself rides authenticated libp2p. Push-to-firewall (L3) is unchanged;
the blocklist *list* endpoint is never federated (point lookups only).

**What the answer is:** an aggregator returns an *evidence aggregate*
(distinct-reporter counts per bucket, scenarios, window) — never a finished
score. Your node **recomputes** the score locally from that evidence using
your own weight table, stranger cap, half-life, and `federation_discount`
(which doubles as the evidence-import discount). A federated answer never
carries anchored corroboration, so it can raise a DNSBL/API score (advisory,
against your threshold) but can never force a block.

**Serving queries (no config needed):** every federated node (i.e. with a
transport) answers `/federloom/repquery/v1` queries — but only from peers
that are **anchored** in its trust store and **not** on its `blocked_peers`
list. Strangers are rejected before their request is read. Defederation
(adding a peer to `blocked_peers`) is the per-peer off switch; a node with
no trust anchors answers nobody.

### `federation_subnet` and `federation_bridge_subnets`

`federation_subnet` names this node's home trust domain (gossip topic). Empty or
`default` uses the single base topic (the default — a flat federation). A named
subnet joins a dedicated topic `federloom/events/v0/<subnet>`.

`federation_bridge_subnets` lists other subnets this node **bridges**: it joins
their topics and re-emits events between them, appending its own id to the
event's origin trace so downstream nodes apply the per-hop `federation_discount`.
Leave empty for a normal leaf node.

**Security:** a bridge can drop, delay, or inject events between subnets. It
cannot force a downstream block (that still requires anchored corroboration) and
imported events are scored by the originator's trust, not the bridge's. Bridge
only subnets you trust; stop bridging a subnet to defederate it.

### observability

Controls the optional observability plane (spec §11.2). Both outputs are
disabled by default — set a non-empty value to enable.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `observability.prometheus_addr` | string | `""` | Address to expose Prometheus `/metrics`, e.g. `:9101`. `""` = disabled. |
| `observability.sqlite_path` | string | `""` | Path to the SQLite event history database. Relative paths are resolved from `store.dir`. `""` = disabled. |
| `observability.sqlite_retention` | duration | `0` | Prune rows older than this duration. `0` = no pruning. |
| `observability.score_gauge_threshold` | float64 | `0` | Emit the `ip_score` Prometheus gauge for IPs above this score. `0` = use `reputation.block_threshold / 2`. |

```yaml
observability:
  prometheus_addr: ":9101"
  sqlite_path: "metrics.db"       # relative to store.dir
  sqlite_retention: 360h          # 15 days
  score_gauge_threshold: 0        # auto: block_threshold / 2
```

### api

Controls the optional local HTTP API (spec §3). Disabled when `addr` is empty.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `api.addr` | string | `""` | Address to listen on, e.g. `:9102`. `""` = disabled. |
| `api.purpose` | string | `""` | Default blocklist filter: `mail`, `web`, `ssh`, or `""` (return all purposes). |
| `api.taxonomy` | map[string][]string | `{}` | Maps purpose labels to reason-code patterns. Patterns support exact strings or prefix wildcards ending in `*` (e.g. `smtp-*`). Empty = use built-in default taxonomy. |

```yaml
api:
  addr: ":9102"
  purpose: "mail"
  taxonomy:
    mail:
      - smtp-*
      - imap-*
      - pop3-*
    ssh:
      - ssh-*
```

### API authentication

The REST API (`api.addr`) is **unauthenticated unless `FEDERLOOM_API_TOKEN` is
set** in the daemon's environment; when set, all API requests require
`Authorization: Bearer <token>`. Bind the API to loopback/VPN for local use, and
**always set the token when the API is reachable off-host** — the blocklist
endpoints are sensitive.

### Recommended never-block additions

Public DNS resolvers (Google, Cloudflare, Quad9) are never-blocked by default.
Large mail/CDN provider ranges are **not** hardcoded (they are broad and change
often — see spec caveat N); add the ones relevant to you via
`enforce.extra_whitelist`, e.g.:

```yaml
enforce:
  extra_whitelist:
    - 35.190.247.0/24    # Google mail egress (example — verify current ranges)
    - 40.92.0.0/15       # Microsoft/Outlook (example — verify current ranges)
    - 104.16.0.0/13      # Cloudflare (example — verify current ranges)
```
Verify current provider ranges from their published SPF/IP lists before adding.

### dnsbl

Controls the optional embedded DNSBL DNS server. Disabled when `addr` is empty.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `dnsbl.addr` | string | `""` | UDP/TCP address to listen on, e.g. `:5353`. `""` = disabled. |
| `dnsbl.zone` | string | `""` | DNS zone served, e.g. `dnsbl.mail.example.com.`. Trailing dot is optional. |
| `dnsbl.min_score` | float64 | `0` | Minimum score for a positive DNSBL response. `0` = use `reputation.block_threshold`. |

```yaml
dnsbl:
  addr: ":5353"
  zone: "dnsbl.mail.example.com."
  # min_score: 0   # defaults to reputation.block_threshold
```

### discovery

Controls automated peer discovery via the libp2p DHT (spec §14). Both flags
default to `true` (opt-out). In `solo` mode these flags are no-ops.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `discovery.advertise` | bool | `true` | Publish this node to the DHT rendezvous point. Set `false` for private-network nodes. |
| `discovery.discover` | bool | `true` | Search the DHT for other swarm peers. |
| `discovery.relay_list_path` | string | `""` | Override the bundled relay list with a local file. `""` = use the embedded list. |

```yaml
discovery:
  advertise: true
  discover: true
  # relay_list_path: ""   # leave empty to use the bundled relay list
```

### bootstrap_peers

A list of well-known libp2p multiaddrs to connect to at startup. Peers are
tried once on boot; the DHT routing table takes over after that. Update this
list when a peer's node key rotates, since key rotation produces a new peer ID.

Defaults to `[]` (empty — no hardcoded peers; discovery via DHT).

```yaml
bootstrap_peers:
  - /ip4/1.2.3.4/tcp/7700/p2p/12D3KooW...
```

## For developers: adding a new config field

1. **Add the struct field** in `internal/config/config.go` with a `yaml:` tag and a comment citing the spec section if applicable.
2. **Set a default** in `Defaults()` if the zero value is not the right production default.
3. **Write a test** in `internal/config/config_test.go` verifying that the default is correct and that the field round-trips through `LoadYAML`.
4. **Add a row** to the appropriate field table in `docs/config.md`. Mark `[secret]` if it must never be committed.
5. **Update any relevant example config** under `deploy/` if the field is operator-facing.
