# Config Documentation Design

**Date:** 2026-06-25
**Status:** Approved
**Output:** `docs/config.md`

## Goal

Write a single reference document (`docs/config.md`) covering every field in `config.yaml` and `config.local.yaml`. Audience: both self-hosting operators and project developers.

`rules.yaml` is out of scope — it has its own inline comments and may get a separate doc later.

## Prose sections

**Overview:** Single YAML file, passed via `--config`. All fields optional; defaults come from `config.Defaults()` in `internal/config/config.go`. Duration values use Go notation only (`168h`, `30m`, `500ms` — no `d` suffix).

**Two-file pattern:** `config.yaml` is committed (no secrets). `config.local.yaml` is generated by bootstrap scripts, holds secrets, and is gitignored. In Docker deployments it is mounted as the sole config at `/etc/federloom/config.yaml:ro` — Go performs no YAML merge; `config.local.yaml` is a complete standalone file. Operator callout: never put secrets in `config.yaml`, never commit `config.local.yaml`.

**Federation modes:** Table of `solo` / `isolated` / `federated` with one-line descriptions and a note that `discovery.*` flags are no-ops in `solo` mode.

**Developer section:** Where to add a new field — struct in `internal/config/config.go`, default in `Defaults()`, test in `config_test.go`, entry in `docs/config.md`.

## Field reference format

Per section: `###` heading, one-sentence purpose, then a table:

| Field | Type | Default | Description |

- Duration fields note accepted format.
- Secret fields marked `[secret]` — belong in `config.local.yaml`.
- Empty/zero-disables fields note `"" = disabled` or `0 = disabled`.
- Enum fields list values inline in the Type column.
- One annotated YAML snippet per major section (below the table).

## Source of truth

All field names and defaults are derived from `internal/config/config.go`. That file is the authoritative source; this doc must stay in sync with it.
